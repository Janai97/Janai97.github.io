# Databases

## Overview

Databases have been an important part of my development throughout the Computer Software Engineering program because they showed me how applications can store, organize, and work with information. Before working with databases, I mostly thought about data as something that was simply stored inside a program. My coursework helped me understand how applications can interact with a separate database and how important the organization of that information is to the overall application.

Through my coursework, I gained experience working with both relational and non-relational databases. I learned how to create, retrieve, update, and delete information and how applications can communicate with databases to provide users with the information they need.

## Artifact: Animal Shelter Dashboard

The artifact I selected for this section is my Animal Shelter Dashboard from CS 340. The project uses Python and MongoDB to store and manage animal shelter records.

I selected this project because it gives me an opportunity to show my experience working directly with a database while also demonstrating how a database can be connected to an application. The project required me to create functionality that could communicate with MongoDB and perform different operations on the stored records.

The Animal Shelter Dashboard uses an `AnimalShelter` class to handle the connection to the MongoDB database. The class contains methods that allow the application to create, read, update, and delete information. This helped me understand how database functionality can be organized within an application instead of putting all of the database operations directly into the main program.

## MongoDB and Python

Working with MongoDB gave me experience with a NoSQL database and introduced me to working with information in a document-based format. Instead of organizing information into traditional rows and columns, MongoDB stores data as documents.

Using Python to communicate with MongoDB allowed me to see how an application can interact with those documents. I worked with database connections, queries, and CRUD operations to manage the animal records.

This project helped me understand that the database is not separate from the application in terms of functionality. The application depends on the database to provide the information it needs, while the database depends on the application to correctly manage that information.

## CRUD Operations

One of the main concepts I worked with in this project was CRUD operations.

CRUD stands for:

- **Create** — adding new information to the database
- **Read** — retrieving information from the database
- **Update** — changing existing information
- **Delete** — removing information from the database

Implementing these operations gave me practical experience working with data instead of only learning the concepts through examples. I was able to see how each operation affects the database and how the application can use those operations to manage records.

Understanding CRUD operations is important because they are used in many types of applications. Whether an application is managing customers, products, students, medical information, or animal records, the basic need to create, retrieve, update, and remove information is often still present.

## Database Design and Organization

Working with the Animal Shelter Dashboard also helped me understand why database organization matters. The information needs to be structured in a way that allows the application to find and work with it efficiently.

I also learned that database design can affect the user experience. If information is difficult to retrieve or poorly organized, the application can become harder to use even if the database itself is functioning correctly.

This helped me think about databases as more than just a place to store information. The way data is organized has an effect on the rest of the application and on the people who eventually interact with that information.

## Improvements

After reviewing the Animal Shelter Dashboard, I identified several areas where I could improve the original project.

One improvement would be expanding the search and filtering functionality. The application could provide users with more ways to narrow down the available records and find specific animals more easily.

I would also improve the way information is displayed. Making the results easier to read would make the application more useful to someone working with a large number of records.

Another improvement would be continuing to organize the database interactions so that the code remains easy to maintain as the application grows. Keeping database-related functionality organized makes it easier to make changes later without affecting unrelated parts of the application.

These improvements also show how my thinking about software has changed since I originally completed the project. At the time, my main focus was getting the required functionality working. Looking at the project now, I think more about usability, organization, maintainability, and how the application could be expanded.

## What I Learned

The Animal Shelter Dashboard helped me become more comfortable working with databases and connecting them to applications. Before working on this project, I understood the basic idea of a database, but working directly with MongoDB gave me a better understanding of how applications actually interact with stored information.

I also learned that database development involves more than simply storing information. The application needs to be able to retrieve the correct information, update it when necessary, and provide useful results to the user.

Working with MongoDB and Python also gave me experience with technologies that I can continue to build on. Understanding how applications communicate with databases is an important skill for software engineering, especially when developing applications that depend on user or business data.

## Professional Growth

My experience with databases has influenced how I think about application development because I now understand the relationship between an application's functionality and the data behind it.

When developing an application, I have to think about what information the application needs, where that information will be stored, and how the application will retrieve and update it. This is something I did not think about as much earlier in the program.

The database experience I gained also connects with other areas of my coursework, including full-stack development. Working with MongoDB, Express, Angular, and Node helped me see how the database can become part of a larger application architecture.

These experiences have given me a stronger foundation for developing applications that work with real-world information.

## Artifact Reflection

Looking back at the Animal Shelter Dashboard, I can see both the strengths of the original project and the areas where I would approach it differently now.

The project successfully demonstrated the required database functionality, but with the experience I have gained since completing it, I would spend more time improving the search and filtering options, the way results are displayed, and the organization of the database-related code.

Being able to look at an older project and identify improvements is one of the things I find useful about creating this ePortfolio. It gives me an opportunity to see how my skills have developed and how I would approach the same type of problem differently today.
