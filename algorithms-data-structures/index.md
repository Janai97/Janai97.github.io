# Algorithms & Data Structures

## Overview

Algorithms and data structures have been an important part of my development as a programmer because they taught me to think about how a problem should be solved instead of only focusing on getting the code to work. Throughout the program, I worked with different ways of organizing information and solving problems, which helped me become more comfortable breaking larger problems into smaller and more manageable steps.

I learned that there is not always one correct way to solve a programming problem. Different solutions can have different levels of efficiency, and the best approach depends on what the application needs to accomplish. Understanding this has helped me become more thoughtful about the decisions I make when writing code.

## Artifact: Algorithms and Data Structures

The artifact selected for this section represents my experience working with algorithms and data structures throughout the program. It demonstrates my ability to take a programming problem, determine what information needs to be stored or processed, and develop a solution based on those requirements.

Working with algorithms required me to think about the individual steps needed to solve a problem. Instead of trying to write everything at once, I learned to break a problem down into smaller pieces and determine what each part of the program needed to accomplish.

Data structures were important because the way information is stored can affect how easily and efficiently a program can work with it. Choosing an appropriate structure can make it easier to search, organize, update, or process information.

## Problem Solving

One of the biggest skills I developed through working with algorithms was problem solving. When I encountered a problem that I did not immediately understand, I learned to break it down and look at each part individually.

This approach helped me become less dependent on already knowing the exact answer. Instead, I became more comfortable researching a concept, testing different approaches, and figuring out why one solution worked better than another.

I also learned that debugging is part of the problem-solving process. When an algorithm does not produce the expected result, the problem may not always be obvious. I had to look at the logic behind the program and determine where the results were beginning to differ from what I expected.

## Efficiency and Performance

Another important lesson from this area of the program was understanding that a working solution is not necessarily the best solution. An algorithm can produce the correct result while still using more time or resources than necessary.

Learning about algorithm efficiency helped me think more carefully about how programs handle information. This became especially important when working with larger amounts of data, where an inefficient solution could have a much greater effect on the performance of an application.

Understanding efficiency also helped me see why software engineers need to consider more than just whether their code works. The way a solution is designed can affect how well an application performs as the amount of data or number of users increases.

## Data Organization

Working with data structures also helped me understand the importance of organizing information in a way that makes sense for the problem being solved.

Different types of data require different approaches. Depending on the situation, information may need to be stored in a way that makes searching, sorting, inserting, deleting, or accessing information easier.

This knowledge has also been useful when working with databases and larger applications. Although data structures and databases are not the same thing, the same general idea applies: the way information is organized affects how effectively an application can work with it.

## What I Learned

The biggest lesson I took away from working with algorithms and data structures is that programming requires more than knowing the syntax of a language. I can know how to write a particular command or function, but I still need to understand how that code fits into the larger solution.

I became more comfortable thinking through a problem before immediately starting to code. I also learned to pay more attention to the consequences of the approach I choose and whether there may be a better way to solve the problem.

These skills have carried over into other courses and projects. When I work on a new application now, I am more likely to think about how the information will be organized, how the different parts of the program will interact, and whether the solution will still make sense as the application becomes larger.

## Professional Growth

My experience with algorithms and data structures has helped me become a better problem solver and has given me a stronger foundation for software engineering. These concepts are important because they can be applied across different programming languages and types of software.

I also understand now that becoming a better programmer is not just about learning more programming languages. It is about learning how to approach problems and how to develop solutions that are organized, efficient, and maintainable.

This is something I plan to continue developing as I enter the software engineering field. I know that I will encounter problems that I have never seen before, and the problem-solving skills I developed through this coursework will help me work through them.
