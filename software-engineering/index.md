# Software Design & Engineering

## Overview

Software design and engineering have been a major part of my development throughout the Computer Software Engineering program. I have learned that building software is not just about writing code and getting a program to run. The design of the application, the way different components work together, how the user interacts with it, and how the code can be maintained all matter when developing a complete software solution.

The artifact I selected for this section is my Computational Graphics and Visualization project from CS 330. I selected this project because it shows a different side of my programming experience than some of my other projects. Instead of primarily working with databases or text-based applications, I had to create a 3D scene and work with graphics programming, objects, textures, lighting, and user interaction.

## Artifact: Computational Graphics and Visualization

For my CS 330 project, I created a 3D scene using C++ and OpenGL in Visual Studio. The scene was based on the Paris map from Overwatch 2, specifically the courtyard area containing the bronze statue.

The project required me to build the scene using basic shapes and then combine those shapes to create a more complex environment. I also worked with textures to make the objects in the scene look more realistic and closer to the reference environment.

Working on this project gave me experience with a type of programming that was very different from many of my other courses. I had to think about the position, size, rotation, and appearance of objects while also considering how the different pieces of the scene fit together.

## Design Decisions

One of the biggest parts of the project was deciding how to break the scene down into individual components. Rather than trying to create the entire environment as one object, I separated it into smaller pieces that could be created and positioned individually.

This made the scene easier to build and gave me more control over each part. I could adjust individual objects without having to completely rebuild the rest of the scene.

I also had to consider how textures would be applied to objects. Textures were important because they helped make the scene look more like the original environment instead of appearing as a collection of plain shapes.

Another important part of the design was the camera. The scene needed to be positioned so that the viewer could see the important parts of the environment. This meant thinking about the camera's position and how objects appeared from the viewer's perspective.

## Development Challenges

This project was also one of the more challenging projects I completed during the program. Working with OpenGL introduced concepts that I had not worked with before, and I had to spend time learning how the different parts of the graphics pipeline worked.

One of the issues I encountered involved loading textures. I was able to successfully load one texture, but when I attempted to load multiple textures, the program would crash. Troubleshooting this issue required me to look closely at how the textures were being loaded and how the resources were being handled.

This experience taught me a lot about debugging. The problem was not always obvious from the point where the program crashed, so I had to work backward and test different parts of the code to figure out what was causing the problem.

## What I Learned

The biggest thing I learned from this project was how important it is to break a complicated problem into smaller pieces. A 3D scene can seem overwhelming when viewed as one large project, but separating it into individual objects and tasks made it much easier to manage.

I also became more comfortable with debugging code that I did not immediately understand. When something went wrong, I had to research the problem, test possible solutions, and make changes based on what I found.

This project also helped me become more comfortable with C++ and working with external libraries and resources. It gave me experience that I would not have gained from only working on traditional applications.

## Professional Growth

This project represents an important part of my growth as a software engineer because it pushed me outside of the types of programming I was already comfortable with. I had to learn new concepts and work through problems that did not have obvious solutions.

It also helped me understand that software engineering requires flexibility. A developer may work with technologies that they have never used before, and being able to learn those technologies and apply them to a project is an important skill.

The experience I gained from this project has helped me become more comfortable approaching unfamiliar programming problems. Even though I do not necessarily plan to specialize in graphics programming, the problem-solving and debugging skills I developed are useful in almost any area of software engineering.

## Artifact Reflection

Looking back at this project now, I can see areas where I could improve the original implementation. I would spend more time organizing some of the code and making certain parts of the scene easier to modify. I would also approach the texture-loading problem differently now because I have a better understanding of debugging and resource management than I did when I first completed the project.

That is one of the reasons I chose this project for my ePortfolio. It shows both what I was able to accomplish and how I have grown since completing the original assignment.
